# Security Policy — ProjectName

The security of ProjectName and its users is important to us.

## Reporting a Vulnerability

If you discover a security vulnerability in ProjectName, please report it responsibly.

### Preferred Reporting Method

Use GitHub's private vulnerability reporting feature, if it is enabled for this repository:

**Security → Report a vulnerability**

This allows you to report vulnerabilities privately to the maintainers.

If private vulnerability reporting is unavailable, contact the repository maintainers through an official contact channel listed in the repository or the Dari Community GitHub organization.

## Please Do Not

- Publicly disclose vulnerabilities before they have been reviewed.
- Open public GitHub Issues containing sensitive vulnerability details.
- Exploit vulnerabilities against other users, systems, or services.
- Access, modify, or delete data that does not belong to you.

## What to Include

When reporting a vulnerability, please provide:

- A description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact.
- Relevant screenshots, logs, or proof of concept, if applicable.
- Possible remediation suggestions, if available.

## Response

The maintainers will make reasonable efforts to review security reports, assess their impact, and address confirmed vulnerabilities.

However, response times, remediation timelines, and security updates are not guaranteed.

## Disclosure

Please allow the maintainers reasonable time to investigate and address reported vulnerabilities before publicly disclosing them.

We appreciate responsible disclosure and the effort you make to protect ProjectName and its users.

Thank you for helping keep ProjectName secure.
